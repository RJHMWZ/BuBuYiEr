# 开发调试工具

适用：Unity 2022.3、当前 Diamond_Loop 模板。无需挂脚本、修改场景或安装第三方插件。

## 1. 开始使用

1. 等 Unity 编译完成，打开菜单 **Tools → BuBuYiEr → 开发调试面板**。
2. 点击 **从主页启动调试**。也可以打开 `Assets/Diamond_Loop/Scenes/Home.unity` 后点击 Play。
3. 在 Game 窗口点击右上角 **调试 F1**，或先聚焦 Game 窗口再按 **F1**。
4. 使用面板里的三个分页；按 **F1 / Esc** 或底部按钮关闭。

打开游戏内面板时游戏暂停，点击不会穿透到棋盘。编辑器窗口自身不会自动暂停。手机开发包可以直接点击右上角入口，面板内容可上下滑动。

## 2. 常用操作

| 操作 | 用法与效果 |
| --- | --- |
| 指定关卡 | 输入关卡编号，点击“进入指定关卡”；编号对应 `Resources/Levels/Level_编号.asset` |
| 上一关 / 下一关 | 按实际存在的关卡编号跳转；首尾会提示，不会越界或循环 |
| 重试本关 | 重新加载当前实际使用的关卡，包括 Inspector 的 `testLevelData` |
| 自动打本关 | 自动按底部方块颜色选择罐子并投放，完成当前关后停止 |
| 连续自动打关 | 自动游玩，胜利后等待结算再进入下一关；失败、卡住或最后一关时停止 |
| 停止自动打关 | 停止后续自动操作；已经开始的投放动画会正常完成 |
| 模拟胜利 | 选择 1～3 星，触发真实胜利效果和结算界面 |
| 模拟失败 | 直接触发失败结算，方便检查失败界面 |
| 跳过引导并重试 | 保存“已看过引导”状态；在关卡中会自动重试 |
| 返回主页 | 退出试玩；下一次正常开始时使用原存档关卡 |
| 暂停 / 倍速 | 支持暂停、0.25x、0.5x、1x、2x、4x；关闭游戏内面板后生效 |
| 设置金币 | 输入目标总数，范围 0～100000000；金币 UI 同步刷新 |
| 五种道具各增加 | 对槽位、磁铁、锤子、钥匙、冷却分别增加指定数量；增量 1～9999，单项总量不超过 99999 |
| 日志 | 游戏内预览最近 12 条；内存最多保留 120 条，错误包含堆栈，可清空或导出 |

跳关、调试重试和模拟结算会进入**试玩模式**：不修改存档的当前关卡、解锁进度或星级，不触发关卡状态对应的插屏广告。试玩胜利后的“下一关”也使用试玩流程；最后一关会提示已到末尾。

试玩只隔离**关卡进度**：正常游玩获得或消耗的金币、道具，以及调试资源修改，仍会写入当前游戏存档。道具的解锁等级继续遵循关卡配置。

关卡切换、重试和模拟结算会恢复 1x，避免暂停时卡在加载或结算流程。倍速影响 `Time.timeScale`，也会影响现有动画与倒计时。

### 自动打关

先进入关卡并完成引导，在“关卡”分页或编辑器窗口点击 **自动打本关 / 连续自动打关**。游戏内面板会自动关闭并开始操作；右上角入口显示“自动中”。再次打开面板会暂停自动操作，关闭后继续，也可以随时点击 **停止自动打关**。编辑器窗口会持续显示投放次数、剩余方块或等待原因。可配合 2x / 4x 加快观察。

自动打关使用试玩模式，不保存关卡进度和星级；启动前会按现有规则自动备份存档。实际收集到的金币仍会保存。运行时接管棋盘点击，手动跳关、重试、返回主页或模拟结算会停止自动操作。

策略优先投放能收集当前底部三层颜色的罐子，考虑传送带剩余容量，避免重复占位；必要时利用空位移开前排罐子，露出后方可收集的颜色，并为后一个罐子保留空位。全程保留原有投放、收集和结算流程。它不会强制填满罐子、改写棋盘、自动购买/使用道具或无限重试。锁定和冰冻罐需要手动处理；复杂的罐子堆叠或颜色顺序也可能卡住。45 秒游戏时间内没有收集进展时会停止并提示，失败或复活界面也会停止，适合开发时观察与回归，不能保证所有关卡必胜。

## 3. 存档备份与恢复

- 首次修改金币、道具、引导状态或重置新玩家前，若没有备份，会自动备份当前游戏存档。
- 仅保留**一份备份**，关闭游戏或退出 Play Mode 后仍保留；不会在每次操作时覆盖它。
- “备份当前存档”可以手动更新备份，已有备份时会二次确认。
- “恢复备份”会覆盖当前游戏存档并返回主页；备份本身保留。
- “重置新玩家”会重置本游戏的玩家数据并返回主页，已有备份保留。恢复和重置均需在界面确认。

只操作模板的 `CBGAMES_PLAYER_DATA` 和工具自己的 `BUBUYIER_DEBUG_PLAYER_BACKUP`，不调用 `PlayerPrefs.DeleteAll()`。

## 4. 手机开发包与日志

在 **File → Build Settings** 勾选 **Development Build** 后打包，即可使用游戏内面板。普通发布包不勾选此选项，调试运行时代码、入口及相关接入逻辑会被条件编译排除。

场景列表应包含 `Assets/Diamond_Loop/Scenes/` 下的 **Home、Loading、Level、Ingame**。本次已修正模板中残留的旧目录路径；后续移动场景时请同步更新 Build Settings。

点击“导出日志”会写入 `Application.persistentDataPath/debug-日期时间.txt`，完整路径显示在面板底部和 Unity Console。面板只收集本次运行、工具初始化后的 Unity 主线程日志，不替代 Unity Profiler、完整 Editor.log 或 Android logcat。

## 5. 后续扩展

| 文件 | 职责 |
| --- | --- |
| `Assets/Diamond_Loop/Scripts/Debug/GameDebugService.cs` | 共享调试指令、试玩关卡、备份与日志 |
| `Assets/Diamond_Loop/Scripts/Debug/GameDebugPanel.cs` | 自动创建游戏内 uGUI，适配新 Input System 与触摸 |

新增调试功能时，先在 `GameDebugService` 增加指令，再在两种界面里添加按钮。调用调试 API 的业务代码需放在 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 内，保持普通发布包可编译。

现有 `IngameManager.testLevelData` 继续可用；主动跳关时工具指定的关卡优先。返回主页后清除工具的关卡覆盖。

设计参考：[UDebug Panel 官方文档](https://github.com/GuillemTools/UDebugPanel/blob/main/DOCUMENTATION.md) 的分类、按钮与数值操作，以及 [In-game Debug Console](https://github.com/yasirkula/UnityIngameDebugConsole) 的运行日志入口。本工具按项目接口自行实现，没有引入或复制付费插件源码。
